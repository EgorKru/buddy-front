## 0. Блокирующие риски перед production (P0)

Деплой публичного production без закрытия критичных пунктов **не рекомендуется**.

| ID         | Проблема                                        | Риск                                   | Действие                                                                                                 | Срок                              |
| ---------- | ----------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------- |
| **P0-F01** | JWT в `localStorage`                            | Утечка токена при XSS                  | Переход на httpOnly cookie + CSRF-стратегия **или** строгий CSP + санитизация; минимум — security review | До публичного prod                |
| **P0-F02** | Токен в query WebSocket URL                     | Попадание в прокси/access logs         | Убрать `?token=`; только STOMP `connectHeaders` (согласовать с backend SC-12)                            | До публичного prod                |
| **P0-F03** | Нет единого контракта ошибок HTTP/WS            | Рассинхрон UX и логирования            | Документ + маппинг кодов в UI; Sentry/логирование                                                        | До первого релиза                 |
| **P0-F04** | `NEXT_PUBLIC_*` — единственный источник API URL | Ошибка env → «тишина» в Network / CORS | Чеклист `.env.example`, валидация при старте (dev), документация rewrites                                | До onboarding новых разработчиков |

**Примечание:** пункты согласованы с backend-документом (JWT в query, секреты, actuator) с точки зрения **клиента**.

## 1. Обзор системы

**Pager Frontend** — SPA на **Next.js (Pages Router)**: авторизация, список чатов, экран чата, звонки 1:1, конференц-комнаты, уведомления, настройки. Данные: **REST** к backend + **STOMP поверх WebSocket** для real-time. Медиа: **PeerJS** (WebRTC) для P2P сигналинга через backend там, где предусмотрено контрактом.

### 1.1 Технический стек

| Компонент        | Версия / детали                                                         |
| ---------------- | ----------------------------------------------------------------------- |
| Framework        | Next.js 13.5.6, React 18                                                |
| Real-time        | `@stomp/stompjs` 7.x, нативный WebSocket (конфигурируемо)               |
| WebRTC           | `peerjs` 1.5.x                                                          |
| UI               | CSS Modules, Tailwind 3, `lucide-react`                                 |
| Состояние        | React Context (`StompProvider`, `MessagingProvider`, `CallProvider`, …) |
| Хранилище сессии | `localStorage`: `token`, `user`                                         |
| PWA / офлайн     | Service Worker `public/sw.js` (кэш статики/медиа, ограниченно)          |
| Качество кода    | ESLint (next), Prettier, Husky, Jest + Testing Library                  |

### 1.2 Границы ответственности

| Слой                                                     | Ответственность                                               |
| -------------------------------------------------------- | ------------------------------------------------------------- |
| **Страницы** `pages/`                                    | Маршрутизация, layout-обвязка, dynamic import тяжёлых экранов |
| **FSD-слой** `src/features`, `src/widgets`, `src/shared` | Фичи (auth, room, chat-sidebar), общий API и конфиг           |
| **Legacy** `components/`, `component/`, `context/`       | Чат, звонки, сокет — постепенная консолидация с FSD           |
| **Утилиты** `utils/`                                     | Дублирование части `shared` (config, api) — **техдолг**       |

## 2. Архитектура

**Тип:** клиентское приложение с **двумя каналами** к backend: HTTP и WebSocket/STOMP. UI — композиция страниц, провайдеров и крупных виджетов чата/комнаты.

### Рис. 1 — Компоненты фронтенда и потоки данных

_Макет для Google Drawings: прямоугольники «Browser», «Next.js Pages», «React Context», «apiRequest (REST)», «STOMP Client», «PeerJS», стрелки к «Backend REST :8080» и «WS ws-native / SockJS»._

### 2.1 Слои (логическая модель)

| Слой         | Путь в репозитории                                               | Назначение                                                         |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Pages**    | `pages/*.js`, `pages/chat/[chatId].js`, `pages/room/[roomId].js` | Маршруты, code-splitting (`dynamic(..., { ssr: false })` для чата) |
| **Features** | `src/features/auth`, `src/features/room`, …                      | Сценарии: логин, создание комнаты, сайдбар                         |
| **Widgets**  | `src/widgets/chat-sidebar`                                       | Крупные блоки UI                                                   |
| **Shared**   | `src/shared/api`, `src/shared/config`, `src/shared/ui`           | HTTP-клиент, URL, переиспользуемые UI                              |
| **Context**  | `context/socket.js`, `context/messaging.js`, `CallContext.js`, … | Глобальное состояние real-time и звонков                           |

### 2.2 Паттерны

| Паттерн                        | Где проявляется                                                                 |
| ------------------------------ | ------------------------------------------------------------------------------- |
| **Provider composition**       | `_app.js`: обёртка authed-маршрутов в `StompProvider` → `MessagingProvider` → … |
| **Public vs protected routes** | `/login`, `/register` без STOMP; остальное — с провайдерами при наличии токена  |
| **Facade API**                 | `src/shared/api/index.js` реэкспортирует `chatAPI`, `authAPI`, …                |
| **Centralized HTTP**           | `apiRequest` в `client.js`: заголовки, 401/403, ошибки                          |

### 2.3 Потоки данных (кратко)

1. **REST:** компонент → `chatAPI` / `authAPI` / … → `fetch(getApiUrl(...))` → JSON.
2. **STOMP:** `StompProvider` → подписки `/user/queue/*`, публикация в `/app/...` (см. раздел 5).
3. **События UI:** `window.dispatchEvent('state-sync')` и др. для синхронизации без прямой связи контекстов.
4. **WebRTC:** PeerJS + сигналы через backend (комнаты/звонки) по контракту экранов `room`, `CallContext`.

## 4. Интеграция с backend

### 4.1 Конфигурация окружения

| Переменная                                           | Назначение                                   |
| ---------------------------------------------------- | -------------------------------------------- |
| `NEXT_PUBLIC_API_URL`                                | База REST, напр. `http://localhost:8080/api` |
| `NEXT_PUBLIC_WS_NATIVE_URL` / производные            | URL нативного WebSocket для STOMP            |
| `NEXT_PUBLIC_WS_URL` / `NEXT_PUBLIC_STOMP_TRANSPORT` | Альтернативы транспорта                      |

**Rewrites** (`next.config.js`): при `NEXT_PUBLIC_API_URL` с `http(s)://` — прокси ` /api/:path* → backend` для same-origin запросов (опционально; клиент может ходить напрямую на порт 8080).

### 4.2 REST — модули `src/shared/api`

| Модуль            | Назначение                                              |
| ----------------- | ------------------------------------------------------- |
| `client.js`       | `apiRequest`, `uploadFileToEndpoint`, обработка 401/403 |
| `auth.js`         | login, register, verification, profile                  |
| `chat.js`         | чаты, сообщения, state                                  |
| `user.js`         | пользователи, поиск                                     |
| `room.js`         | комнаты                                                 |
| `notification.js` | уведомления                                             |
| `turn.js`         | TURN credentials                                        |

### 4.3 Согласование с backend API

Карта должна поддерживаться в паре с разделом **5. API Reference** backend-документа. Версионирования `/api/v1/` на фронте **пока нет** (техдолг MT-05 backend).

## 5. WebSocket / STOMP (клиент)

### 5.1 Подключение

| Параметр       | Реализация                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------- |
| Транспорт      | По умолчанию **native** WebSocket (`NEXT_PUBLIC_STOMP_TRANSPORT`)                               |
| Аутентификация | `connectHeaders`: `Authorization` / `X-Authorization: Bearer` + **query `token`** (риск P0-F02) |
| Реконнект      | `reconnectDelay` из `config.stomp.options`                                                      |

### 5.2 Подписки (пример из `StompProvider`)

| Destination              | Назначение                                                                  |
| ------------------------ | --------------------------------------------------------------------------- |
| `/user/queue/errors`     | Ошибки; при тексте про аутентификацию — сброс сессии и редирект на `/login` |
| `/user/queue/state-sync` | `STATE_SYNC` → `CustomEvent('state-sync')`                                  |

Остальные очереди (`/user/queue/messages`, `calls`, `notifications`, …) подключаются в специализированных хуках/контекстах — **актуальный перечень зафиксировать в код-ревью и дополнить таблицей при рефакторинге**.

### 5.3 Публикация (client → server)

Соответствует backend **§5.2** (`/app/chat.sendMessage`, `/app/call.signal`, `/app/room.signal`, …). Точные destination — в модулях `context/messaging`, обработчики звонков/комнат.

### Рис. 3 — Диаграмма последовательности: открытие чата

_Макет: User → Page → Stomp connect → subscribe topics → REST load history → render messages._

## 7. Функциональные требования (фронт)

Префикс **FF** = Frontend Functional. Связь с backend **FR-\*** по смыслу.

| ID      | Требование                                                                                                                  |
| ------- | --------------------------------------------------------------------------------------------------------------------------- |
| FF-A01  | Формы login/register: валидация, отображение ошибок API, без «тихого» сабмита (`noValidate` + явная валидация где внедрено) |
| FF-A02  | После login — сохранение `user`+`token`, редирект на домашнюю                                                               |
| FF-CH01 | Список чатов и переход в `/chat/[id]`                                                                                       |
| FF-CH02 | Отправка/получение сообщений согласованно с REST + WS                                                                       |
| FF-C01  | UI звонка 1:1 (входящий/исходящий) через контекст звонков                                                                   |
| FF-R01  | UI комнаты: join, медиа, сигналы — см. `pages/room`                                                                         |
| FF-N01  | Глобальные уведомления (`GlobalNotifications`)                                                                              |
| FF-U01  | Настройки / профиль в рамках доступных backend endpoint                                                                     |

Пометка **[!]** — расхождение или долг:

| ID       | Проблема                                                                  |
| -------- | ------------------------------------------------------------------------- |
| FF-[!]01 | Дублирование `utils/config` vs `src/shared/config` — риск расхождения URL |
| FF-[!]02 | Часть импортов `@/utils/api` vs `@/shared/api` — единый вход желателен    |

## 8. Нефункциональные требования (NFR)

Шкала: **P0** production-stop · **P1** высокий · **P2** средний · **P3** низкий.

### 8.1 Производительность

| ID     | Требование                             | Текущее            | Целевое                                       | Статус       |
| ------ | -------------------------------------- | ------------------ | --------------------------------------------- | ------------ |
| PF-F01 | FCP на login/home                      | Не измерено        | LCP < 2.5s (mobile)                           | Не выполнено |
| PF-F02 | Размер бандла чата                     | `dynamic` без SSR  | Отдельный chunk, анализ `source-map-explorer` | Частично     |
| PF-F03 | Частота ре-рендеров в списке сообщений | Не профилировалось | Мемоизация / виртуализация при > N сообщений  | Не выполнено |

### 8.2 Надёжность и UX сети

| ID     | Требование                  | Текущее                  | Целевое                    | Статус   |
| ------ | --------------------------- | ------------------------ | -------------------------- | -------- |
| RL-F01 | Ошибка «backend недоступен» | Сообщение в `apiRequest` | Единый toast + retry       | Частично |
| RL-F02 | WS reconnect                | Есть delay в STOMP       | Индикатор «нет соединения» | Частично |

### 8.3 Безопасность (клиент)

| ID     | Требование      | Текущее              | Целевое                          | Статус       |
| ------ | --------------- | -------------------- | -------------------------------- | ------------ |
| SC-F01 | Хранение токена | localStorage         | httpOnly cookie или hardened SPA | Не выполнено |
| SC-F02 | CSP / XSS       | Не задокументировано | Политика + audit зависимостей    | Не выполнено |
| SC-F03 | Токен в URL     | WS query             | Только headers                   | Не выполнено |

### 8.4 Поддерживаемость

| ID     | Требование       | Текущее       | Целевое                                | Статус       |
| ------ | ---------------- | ------------- | -------------------------------------- | ------------ |
| MT-F01 | Структура FSD    | Частично      | Полная миграция `components` → `src/`  | В процессе   |
| MT-F02 | Тесты            | Jest настроен | Покрытие критичных хуков и API-обёрток | Не выполнено |
| MT-F03 | Env документация | Разрозненно   | `.env.example` + раздел в README       | Частично     |

### 8.5 Сводная таблица NFR (фронт)

| Категория       | Всего (пример) | Выполнено | Частично | Не выполнено |
| --------------- | -------------- | --------- | -------- | ------------ |
| Performance     | 3              | 0         | 1        | 2            |
| Reliability     | 2              | 0         | 2        | 0            |
| Security        | 3              | 0         | 0        | 3            |
| Maintainability | 3              | 0         | 2        | 1            |

## 9. Service Worker

| Аспект                                     | Поведение                                                                  |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| Файл                                       | `public/sw.js`                                                             |
| Регистрация                                | `_app.js` → `register('/sw.js')`                                           |
| GET к `/`, `/chats`, `/login`, `/register` | `fetch` без кэша из списка статики для части путей                         |
| Не-GET                                     | Не перехватывается (пропуск)                                               |
| Медиа                                      | Кэш изображений/аудио по префиксам `/api/chats/...` (same-origin сценарий) |

**Риск:** рассинхрон версий после деплоя — предусмотреть стратегию обновления SW и инвалидации кэша.

## 15. Глоссарий

| Термин     | Определение                                             |
| ---------- | ------------------------------------------------------- |
| **FSD**    | Feature-Sliced Design — методология структуры фронтенда |

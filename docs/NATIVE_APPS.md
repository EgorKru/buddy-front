# Pager for Windows, macOS, Android and iOS

Both native shells use the production web client at `https://pager.website`, so REST, STOMP,
WebRTC and E2EE behavior stay shared with the browser build.

## Windows and macOS

Development requires the Next.js server and Electron in two terminals:

```powershell
npm run dev
npm run desktop:dev
```

Create an unsigned Windows installer:

```powershell
npm run desktop:build:win
```

Create an unsigned macOS DMG on macOS:

```bash
npm run desktop:build:mac
```

Electron grants camera, microphone, notifications and screen capture only to configured Pager
origins. External HTTP links open in the system browser. Screen sharing selects the full display
after the user invokes the share action; this path is covered by the browser/WebRTC E2E suite and
the desktop security policy has unit tests.

Set `PAGER_APP_URL` when packaging for another environment. A public release should be signed with
an Authenticode certificate; keep the certificate outside the repository and provide it through CI
secrets.

## Android

The generated Capacitor project targets Android API 36 and declares optional camera/microphone
hardware so messaging still works on devices without either sensor:

```bash
npm ci
npm run android:sync
npm run android:open
```

An unsigned debug APK is built by `.github/workflows/android.yml`. A Play Store release still needs
an upload key, a release signing configuration, production icons/splash assets, privacy policy and
store metadata. Keep all signing material in CI secrets, never in Git.

## iOS and iPadOS

The Xcode project is generated by Capacitor. Synchronization and final builds require macOS, Xcode,
CocoaPods, an Apple Developer account and signing credentials:

```bash
npm ci
npm run ios:sync
npm run ios:open
```

Camera, microphone and photo-library purpose strings are already included in `Info.plist`. Before
App Store distribution, replace the generated icons/splash assets, configure the team and bundle
identifier, and test calls on physical devices.

## Mobile screen sharing

WebRTC camera/microphone calls run through the shared web client. Mobile operating systems require
native capture extensions for broadcasting the device screen (ReplayKit Broadcast Extension on
iOS and MediaProjection/foreground service integration on Android). The current MVP intentionally
does not claim mobile device-screen broadcasting: the web UI reports it as unavailable when the
embedded browser lacks `getDisplayMedia`. Browser and desktop screen sharing are implemented.

## Delivery automation

- `.github/workflows/desktop.yml` builds Windows `.exe` and macOS `.dmg` artifacts on version tags.
- `.github/workflows/android.yml` builds an unsigned debug `.apk` on tags or manual dispatch.
- `.github/workflows/ios.yml` performs an unsigned iOS Simulator compile on manual dispatch.
